# Marmo-Core 脅威モデル

English version: [threat-model.md](threat-model.md).

最終レビュー日: 2026-11-27

## 対象と保護資産

この文書では、プロセス内のカーネル、Policy Gateway、Context Compiler、State Store、監査ログ、LLM アダプター、Tool Runtime、Connector の契約、MCP ゲートウェイを対象とします。保護する資産は、ユーザーの意図、認証情報、非公開データ、ファイルとネットワークの接続先、実行権限、永続化された状態、監査記録の完全性です。

## 信頼境界

- ユーザーのゴールと、ローカルでレビュー済みの Skill 指示は信頼された指示です。
- Memory 本文、外部／ファイル／Web の内容、Tool の結果、Agent の結果は、リソースのパッケージ `trust_level` にかかわらず信頼されない内容です。
- LLM の出力は提案です。Tool の呼び出しが有効なのは、リソースが有効化され、その正確な操作が有効化／実行ゲートで許可された場合に限ります。
- opt-in のタスク充足ルーティングでは、観測されたリソース契約をレビュー済みの宣言として扱い、実際の能力を証明するものとはみなしません。未知の契約や、実行時に満たせない前提条件を根拠に十分性を確認することはできません。凍結済みの TaskSpec は権限エスカレーションをまたいで維持され、メタデータによってユーザーの要件が暗黙に置き換えられることはありません。依存関係の閉包と最終的に描画される payload は、モデル呼び出しの前に検査されます。これらの検査は、メタデータの正しさや実際のタスク完了を証明するものではありません。候補の探索では、呼び出し元に提示された registry が見えることを前提とします。一時的な候補用ポリシーコンテキストでは、選択時に限って必須権限を緩和します。独立した探索 ACL はありません。ホストは機密リソースをその registry から除外する必要があります。実際の有効化と実行は引き続きゲートで制御されます。
- どの set selector の後でも、Kernel は選択された各リソースが宣言する依存関係を候補プールまたは registry から追加します。依存先が見つからない、activation で拒否される、またはより上位のリソースと競合するリソースは除外されます。選択されたリソースが名前を挙げたからといって、追加された依存先を信頼することはありません。同じ activation gate を通し、依存関係を保持する compiler は、そこで依存先が除外されたリソースも文脈に含めません。除外されたリソースは skipped として報告されます。
- 設定されている場合、Kernel が制御するモデル呼び出しと Resource 呼び出しの前にタスク予算を確認します。予算イベントログは rollback 後も保持され、resume 時に異なるポリシーを使うと拒否されます。ハンドラー内で発生する外部料金は Resource が宣言した見積もりに依存します。プロバイダーの利用量が予約上限を超えた場合は記録され、以降の処理を停止します。
- 一時停止したタスクでは、選択済み Resource の識別情報と、コンパイル済みの実行コンテキスト fingerprint が保持されます。resume 時に選択した Resource 定義を確認し、内容が変わっていれば停止します。これにより、カタログの更新で承認済みタスクの実行先が暗黙に変わることを防ぎます。
- `structured_task` Agent は、宣言済み依存関係の推移閉包だけを registry に含む子 Kernel で実行されます。子には Agent が宣言した権限だけを渡し、各子操作にポリシーゲートと人間の承認を適用します。子の Tool 結果は補償処理のため親タスクに記録されます。ネストした Agent 呼び出しは親のコスト台帳を共有し、設定された深さと Agent 累積コスト上限に従います。
- `MCPGatewayServer`（`marmo mcp-serve`）の MCP クライアントは、LLM の出力と同じく信頼境界の外にあります。クライアントが送るゴールと引数は提案です。ポリシーコンテキストはゲートウェイを起動した運用者が固定し、どのメッセージからも変更できません。Tool を呼べるのは、同じセッションの `search_tools` がその Tool を返した後だけで、返すには activation gate の通過が必要です。各呼び出しは Tool Runtime の execution gate を通ります。この経路には承認者がいないため、escalate は拒否になります。事前の承認は運用者が `approved_resources` で与えます。Tool の結果をクライアントに返すと、そのセッションは信頼されない内容を参照したものとして扱います。ゲートウェイに discovery ACL はなく、公開しなかった Tool も名前と理由を返すため、機密のリソースは公開する registry に含めないでください（ADR 0016）。
- Tool ハンドラーとシークレットリゾルバーは LLM の境界の外にあります。シークレット値はハンドラーの呼び出し直前にのみ実体化されます。
- 既定の thread timeout は待機を終了させますが、ハンドラーを停止できません。POSIX の `timeout_mode="process"` では、import 可能なハンドラーをプロセスグループで実行し、期限に達すると停止します。Windows ではワーカーだけを停止すると子プロセスが残るため、このモードを拒否します。すでに外部サービスが受け付けた副作用を取り消すことはできません。タイムアウトした操作は自動で再試行または置換されません。オペレーターが先に結果を照合する必要があります。

信頼されていない内容は、その payload のテキストから閉じることのできない区切りの内側にシリアライズされます。シグナルの強い上書き指示、プロンプト抽出、Tool 指示、シークレット窃取のパターンは、一致したテキストを保持せずに監査されます。モデルが信頼されていない内容を参照した後は、リソース自体が以前または全体として承認済みでも、その後の書き込み／外部向け／不可逆な呼び出しに引数単位の人間承認が必要です。

## 隔離契約

Connector と Tool は `isolation_level` を宣言します。

- `L0`: 隔離なし。低リスクまたは読み取り専用の用途に限るのが適切です。
- `L1`: プロセス分離、タイムアウト、リソース制限。
- `L2`: L1 に加え、ファイルシステム／ネットワークの制限。
- `L3`: 任意の拡張機能が提供するコンテナーまたは VM による隔離。

Policy Gateway は宣言値を `PolicyContext.minimum_isolation_level` と比較し、両方の値を監査します。Core は L0〜L2 の宣言を受け入れます。ランタイムが L3 拡張機能を明示的に提供しない限り、L3 は拒否されます。宣言は Connector の契約であり、それだけで保証の証明にはなりません。組み込み Shell Connector は、実行ファイル許可リスト、`shell=False`、制限された cwd／環境変数／出力、タイムアウトによって L1 を提供します。File と SQLite は、ファイルシステムのルートまたはデータベースのパスを制限して L2 を提供します。HTTP は Connector のホスト許可リストがあれば L2、なければ L1 を提供します。Connector のテストとデプロイ時の制御で、これらの保証を引き続き検証する必要があります。

## 脅威と制御

| 脅威 | 主な制御 | 残存リスク |
| --- | --- | --- |
| 直接／間接プロンプトインジェクション | 内容／指示のラベル、エスケープされた境界、検出器の監査、誘発された副作用に対する操作単位の HITL | モデルが最終回答で敵対的なデータを使う可能性は残る。検出器は意図的に完全ではない |
| シークレットまたは非公開データの流出 | `SecretRef`、遅延解決、出力／エラーの伏せ字化、ホストの許可／ブロックリスト、機微な外部入力に対する HITL | ハンドラーに明示的に渡したシークレットは、悪意あるハンドラーが受け取る |
| 破壊的な操作 | 引数を考慮した deny／escalate ルール、正確な操作に対する承認、dry-run、同じゲートを通す補償 | 新しいコマンド表現が字句ルールを回避する可能性がある |
| 過剰な権限 | 宣言済み権限、既定 deny の信頼ポリシー、有効化／実行ゲート、Agent 委譲権限の部分集合チェック、依存関係に限定した `structured_task` 子 registry | 悪意のあるプロセス内ハンドラーが明示的に与えられた権限を悪用する可能性がある。依存関係宣言とメタデータは信頼された入力である |
| 実行隔離の弱さ | L0〜L3 の宣言、最低レベルのゲート、組み込み Connector の L1／L2 制限、既定では L3 を利用不可にする | DNS rebinding とファイルシステム TOCTOU はデプロイ上の懸念として残る。L1 はファイルシステムのサンドボックスではない |
| タイムアウト後もローカルハンドラーが動き続ける | import 可能なハンドラーへの任意のプロセスタイムアウト。タイムアウト結果では自動 recovery を停止 | 互換性のため thread モードも利用可能。プロセスを終了しても、確定済みの外部副作用は取り消せない |
| 並行実行や中断した実行による副作用の重複 | 副作用の前にタスクごとの実行権を確保（JSONL と SQLite のストアは OS のファイルロック）、記録済みの結果を再実行しない呼び出しジャーナル、結果不明の呼び出しは再試行せずエスカレート、`cancel` 後の終端状態を上書きしない | 独自の State Store は `_execution_guard` を実装しない限り他プロセスを排他しない。ファイルロックはファイルシステムに依存する（ネットワークファイルシステムでは効かない場合がある）。結果の保存前に止まった呼び出しは人が結果を確認する必要がある |
| レビューした引数と実行される引数の食い違い | `modify` の回答は記録前に Tool の入力スキーマで検証し、一時停止した呼び出しまたはプランのステップに保存する。不正な修正では依頼が保留のまま残る | レビュー対象は引数であり、ハンドラーの作用そのものではない |
| 悪意あるリソースパッケージ | trust level、明示的な権限、ローカル検証 | パッケージ署名と配布レジストリは未導入。trust、権限、副作用、隔離の宣言を偽装するパッケージは、メタデータに基づくルーティングとゲートを通過しうる。`benchmarks/run_forgery_benchmark.py`（[`benchmarks/README.md`](../benchmarks/README.md)）は、偽装する宣言ごとに Tool・Skill・Agent の偽装資源が選択され、activation を通過し、モデルに渡り、execution gate を通って何もしない代替ハンドラーに届く頻度を継続的に測る。偽装資源に対して同梱のハンドラーは実行しない。activation を通過するのは、ゲートが見る宣言をすべて偽装した資源だけである。一部だけの偽装でも選択はされ、正規の資源を押しのける。説明文にタスクの語を詰め込み、呼び出し側が持たない権限を正直に宣言した資源は、集合ソルバーに escalate を返させ、人にその権限（ベンチマークでは `net.external`、`message.send`）の付与を求めさせる。`Kernel(gate_aware_selection=True)`（既定はオフ、ADR 0014）は、権限や承認にかかわらずゲートが拒否する候補を、選択集合と escalate の理由から外す。信頼度・副作用・隔離の宣言がゲートを通る資源には効かない |
| MCP クライアントがゲートウェイ経由で Tool を操作する | 運用者が固定するポリシーコンテキスト、`search_tools` が返した Tool だけを呼べる制限、呼び出しごとの activation／execution gate、escalate の拒否、返した結果の未信頼内容としての追跡、区切りと上限付きの出力 | ゲートウェイが見るのは自分のセッションだけで、クライアントのモデルがほかに読んだ内容は見えない。事前承認した副作用のある Tool は、結果を返す前なら 1 回実行できる。公開する registry にある Tool の名前、説明、拒否理由はクライアントに見える |
| 状態／監査情報の漏えいまたは改ざん | `SecretRef` の永続化チェック、伏せ字化、ハッシュチェーン付き監査ログ | ハッシュチェーンは変更を検出するが、リモートアテステーションは提供しない |

## リリースレビュー

各リリースの前に、新しい Connector、信頼境界の越境、検出ルール、権限の既定値、隔離の主張、未解決の Critical／High の指摘をレビューしてください。緩和されていない Critical／High のリスクがある場合、リリースを進めてはいけません。脅威モデルまたは許容する残存リスクが変わった場合は、日付入りの記録をここに追加してください。

## レビュー履歴

- 2026-11-27: Tool 実行への 2 本目の経路として MCP ゲートウェイをレビュー。Kernel と同じ Policy Gateway と Tool Runtime を使い、MCP クライアントを信頼せず、escalate の代わりに拒否する。事前承認と registry の公開範囲は運用者の責任とした。
- 2026-11-09: opt-in のタスク充足境界を記録。宣言された能力は仮定のままであること、凍結された要件、完全な文脈依存関係、最終 payload の検証が既存の有効化／実行ゲートを補完することを明記。
- 2026-09-25: 期限の挙動をレビュー。プロセスモードでは import 可能なローカルハンドラーを停止する一方、外部副作用の結果は不確実なままであることを記録。タイムアウト後の自動再試行とフォールバックを削除。
- 2026-09-25: Agent 委譲をレビュー。子 Kernel を宣言済み依存関係の推移閉包と Agent から付与された権限に限定し、子の副作用は親タスクの監査／状態と補償経路に記録することを明記。プロセス内ハンドラーはサンドボックスの外にある。
- 2026-07-23: 0.4.0 v2 リリース候補の、新しい実行経路、権限の既定値、信頼境界、隔離の主張をレビュー。緩和されていない Critical または High の指摘はなかった。
- 2026-07-23: Agent 委譲と組み込み HTTP／File／Shell／SQLite Connector をレビュー。具体的な L1／L2 制御と残存リスクを記録。
- 2026-07-22: 初回のモデルを記録。Memory／Tool の内容境界、プロンプトインジェクションの監査と副作用への HITL、L0〜L3 のポリシー契約を追加。
