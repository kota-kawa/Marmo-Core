# 0003. 関連度成分を絶対値にし、SKILL.md 本文を割り引いた BM25F で索引する

- 状態: Accepted
- 日付: 2026-09-19
- 根拠: 11648de1、3de214ca（PR #13）、CHANGELOG 0.6.0、`benchmarks/README.md`

## 文脈

関連度成分は BM25 を「同じ結果集合の最高点」で割った相対値だった。どのクエリでも 1 位が
高得点になるため、`min_relevance` や `seed_min_relevance` などすべての足切りが機能せず、
無関係なゴール（ラーメン）が 0.63 で AWS Step Functions のスキルを起動していた。
また SKILL.md 本文（中央値 667 トークン）がメタデータ（34 トークン）と同じ重みで索引され、
本文の偶然の語で長い Skill が本命の Tool に勝っていた。

## 判断

- 関連度は「クエリ語をすべて 1 回含む文書」を 1.0 とする絶対値にする。
- メタデータと本文を BM25F の 2 フィールドにし、本文は `BODY_FIELD_WEIGHT=0.25` で割り引く。
- `RuleBasedSetSelector`（既定）も `min_relevance` を尊重する。`Kernel(min_relevance=...)`
  を公開するが既定は 0.0（コーパスごとに校正するため）。
- ベンチマークの既定しきい値を 0.55 → 0.35 に読み替える。

## 影響

- 既存利用者のスコアと順位が変わる。旧尺度で校正したしきい値は再校正が要る。
- 絶対化の代償として、基準文書を上回った文書が 1.0 で同点になり、120 件中 2 件が 1 位から
  外れる（hit@1 66.7% → 65.0%）。全体では BM25F により hit@1 61.7% → 65.0%、
  paraphrase 31% → 46%。
- 関連度成分を差し替える今後の改良は、第2層（集合選択）の Coverage と abstain 精度まで
  見て採否を決める。

## 代替案

- 相対正規化を維持して `min_seed_token_matches` のような回避策を積む: 症状ごとの
  パッチになり、棄権が原理的に成立しないため却下。
- 本文を索引しない: paraphrase / abstract の recall が落ちるため却下。
