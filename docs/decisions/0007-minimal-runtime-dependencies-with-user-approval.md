# 0007. 実行時依存は最小限に保ち、追加はユーザーの確認を取る

- 状態: Accepted
- 日付: 2026-09-23
- 根拠: `0001-single-runtime-dependency.md` を置き換える。`pyproject.toml`

## 文脈

0001 は実行時依存を `python-dotenv` の 1 つに固定し、追加には issue での合意を求めていた。
組み込み先の依存解決を汚さない目的は今も有効だが、依存を 1 つに固定すると、標準ライブラリで
書くと保守コストや不具合の余地が大きくなる場面でも、自前実装を強いることになる。

## 判断

- 実行時依存は最小限に保つが、`python-dotenv` だけに固定はしない。まず標準ライブラリと
  既存の依存で賄えるかを検討する。
- 新しい実行時依存を追加する前に、必要性、標準ライブラリや既存の依存で代替したときの
  コスト、インストールサイズ・推移的依存・ライセンス・組み込み先との衝突の影響をユーザーに
  示し、確認を取る。確認なしに `pyproject.toml` の `dependencies` を変更しない。
- 必須にしなくてよいものは、optional extra やプロバイダ ABC（`EmbeddingProvider` /
  `CrossEncoderProvider` / `LLMProvider`）の背後に置き、コアは依存なしで動くようにする。
  ベンチマーク用は `benchmark` extra、開発ツールは `dev` extra。

## 影響

- 追加した場合は、理由と影響を PR 本文に書き、`CHANGELOG.md` の `## [Unreleased]` に
  追記する（利用者のインストール内容が変わるため）。
- 0001 の分離（モデル系は extra、コアは ABC）はそのまま引き継ぐ。

## 代替案

- 0001 のまま `python-dotenv` だけに固定する: 自前実装の保守コストが見合わない場面でも
  依存を足せないため却下。
- 確認なしで依存の追加を許す: 組み込み先の依存衝突とインストールサイズの問題が再び出るため
  却下。
