# 0009. タスク予算は実行前の予約と追記型の精算で管理する

- 状態: Accepted
- 日付: 2026-09-25
- 根拠: `marmo_core/budget.py`、`marmo_core/kernel.py`

## 文脈

集合選択の `SelectionContext.budget_cost` は存在したが、Kernel は値を渡していなかった。
選択後のモデル呼び出し、Tool の再試行、Agent 実行も同じ上限を共有していなかった。

## 判断

- `TaskBudget` で通貨、Resource の `cost_estimate` の単位、モデルの入力・出力単価と
  呼び出しごとの最大 token 数を明示する。通貨と Resource 単位が違えば拒否する。
- 予算設定をタスク作成時の state event に固定する。再開時に設定が異なれば拒否する。
- 各モデル呼び出しと各 Resource 実行試行の前に予算を予約し、結果が得られたら精算する。
  モデルの使用量が得られなければ予約額全額を課金額とみなす。例外で使用量が不明な場合は
  予約を保持し、過小計上を避ける。
- rollback は実行結果の state projection を戻しても、予算イベントを巻き戻さない。
- 既定の RuleBased selector は残額を集合選択に使う。他の selector の出力も Kernel が
  再検査する。

## 影響

Resource の `cost_estimate` は、明示した通貨での実行一回分の見積りとして扱う。
Resource 内部で別の有料 API を呼ぶ場合、その費用は利用者が見積りに含める必要がある。
モデルの実使用額が予約額を超えた場合は実額を記録して以後の作業を停止する。
この予算は請求額の上限保証ではなく、Kernel が把握できる費用の事前承認上限である。

## 代替案

selector の `budget_cost` だけを設定しても再試行やモデル呼び出しを抑止できないため採らない。
使用量の確定を待ってから予算を減らす方式は並列実行で超過し得るため採らない。
