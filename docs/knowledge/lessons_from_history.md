# 履歴からの知見

git 履歴（52 コミット、PR #1〜#14、CHANGELOG 0.4.0〜0.6.0）から抽出した、繰り返し
効く教訓。根拠の commit / PR / バージョンを併記する。新しい教訓は該当する節に 1 行で足し、
根拠を付ける。

## リリース・パッケージング

- バージョンは `marmo_core/_version.py` と `pyproject.toml` の 2 か所にある。ずれると
  `scripts/release_check.py` が止める。リリースコミットは毎回この 2 つと `CHANGELOG.md` を
  変える（9929ed89、583473e1）。
- タグと同梱バージョンが違うと `release.yml` の build が止まる。タグの打ち間違いでの公開を
  防ぐため（PR #8）。
- CHANGELOG に現行版の `## [x.y.z] - YYYY-MM-DD` 節が無いと release_check が通らない
  （PR #8）。
- 追跡ファイルを 1 つ足すたびに `check-manifest` が落ちる。sdist に入れるなら
  `MANIFEST.in`、リポジトリ専用なら `[tool.check-manifest] ignore`。開発者向け文書は
  ignore が定位置で、一度 sdist に入れてから外した経緯がある（6d54dfde → 1fb4601d）。
- sdist には「その中でテストを回すのに要るもの一式」（フィクスチャ、examples、scripts、
  `.env.example`）を入れ、抽出した sdist から全テストが通ることを確認する（PR #3、#4）。
- Docker イメージ内でもテストが回り、テストが `release_check.py` を呼ぶ。`.dockerignore` は
  `*.md` を除外しつつ `!CHANGELOG.md` で残している（9d67d171、7a190ceb）。
- PyPI 版と `main` の中身が大きく違うのに同じ版番号を名乗っていた（0.4.0）。解消のためだけの
  リリースを切った（0.5.0、583473e1）。`main` に利用者に見える変更が溜まったら版を上げる。
- 最初のインポートで `.pyc` 38 件と WSL の `*:Zone.Identifier` 75 件がコミットされていた。
  `.gitignore` で対処（7a1d74f3）。
- 公開は Trusted Publishing。PyPI 側の登録、GitHub Environment（`pypi` / `testpypi`）、
  非公開の脆弱性報告の有効化はリポジトリの外で手作業が要る（PR #8）。

## テスト・CI

- `-W error::ResourceWarning` は必須。Python 3.14 で SQLite 接続の閉じ忘れを検出した（PR #3）。
- ruff は `E4,E7,E9,F` に絞って安定させた（dcc63101）。mypy は `marmo_core` のみ。
- **モック LLM だけのテスト（419 件）では、実プロバイダでツール呼び出しが全滅していることを
  検出できなかった。** 実機で一度通すと HTTP 400 系がまとめて見つかった（PR #11）。
  プロバイダの wire 形式に触る変更は、固定応答テストと実機確認をセットにする。
- 同梱の 1,030 件カタログを実モデルで一通り使うと、検索の偏り、失敗が隠れる経路、resume の
  落とし穴が見つかった（PR #12）。大きなカタログと小さな Tool 群を混ぜた状態で試す。
- 修正には回帰テストを付ける。レビューで回帰テストの無い修正が 3 件見つかり後から足した
  （3de214ca）。
- 「順位は変わらない」という主張を実測で反証したら、主張ではなく数値を書く
  （3de214ca: hit@1 66.7% → 65.0%）。
- 互換性は `tests/fixtures/compat/v0.3.0` の凍結物で守る（509d5f68）。

## LLM プロバイダー連携

- リソース id のドットは OpenAI / Anthropic のツール名文法で拒否される（HTTP 400）。
  `ToolNameCodec` で往復する（PR #11）。
- 現行 OpenAI モデルは `max_completion_tokens` を要求する。endpoint で既定を選び、未対応と
  返されたら 1 回だけ切り替える（PR #11）。
- Groq の Cloudflare は urllib 既定の User-Agent を 403（error 1010）で弾く。
  `marmo-core/<version>` を付ける（PR #11）。
- `OPENAI_REASONING_EFFORT=none` は Groq で初回から 400。既定は空にし、プロバイダ固有と明記
  （0.5.0）。以前は逆に `none` を既定にしていた（PR #2、#5）。
- 埋め込みプロバイダが `api.openai.com` に固定されていたため、Groq / vLLM / Ollama 用の
  キーが OpenAI に送られ、キーの一部をエコーした 401 が返った（4f18512e）。同じ設定は
  チャットと埋め込みの両方で同じ場所から解決する。
- プロバイダのエラー本文は例外・ログに出る前に伏せ字にする。OpenAI の 401 は送ったキーの
  一部を返す（0.5.0）。
- Claude Sonnet 5 は adaptive thinking が既定で有効で、出力上限 4096 固定では切れる。
  `ANTHROPIC_MAX_TOKENS` を必須の環境変数にした（PR #5）。
- HyDE、LLM 再ランク、`LLMSetSelector` はモデル呼び出しの失敗を黙って飲んでいたため、
  設定ミスが見えなかった。`logging` で 1 回警告し `last_failure` に保持（4f18512e）。
- Tool が 1 つも無いときはシステムプロンプトにそう書く。書かないと gpt-oss が存在しない
  ツールを呼ぶ（PR #11）。
- HyDE の書き換えプロンプトは英語出力に固定し、日本語ゴールを英語メタデータに当てる（PR #11）。

## 検索・ルーティング

- BM25 を同じ結果集合の最高点で割る相対正規化では、どのクエリでも 1 位が高得点になり、
  足切りが機能しなかった（ラーメンの話題が 0.63 で Step Functions のスキルを起動）。
  クエリ語をすべて 1 回含む文書を基準にした絶対値へ（0.6.0、ADR 0003）。
- 絶対化の代償は 1.0 で頭打ちになった文書同士の同点で、120 件中 2 件が 1 位から外れた。
  代償は隠さず書く（3de214ca）。
- SKILL.md 本文はメタデータの約 20 倍長く、偶然含まれる語で勝つ。BM25F の 2 フィールドに
  分け、本文を `BODY_FIELD_WEIGHT=0.25` で割り引く（0.6.0）。
- 全種別まとめての単一 `top_k` では、1,000 件の Skill が候補枠を埋めて Tool が 0 件になった
  （正解 Tool は 37 位）。枯渇した kind だけ kind 限定検索で補充する（0.5.0）。補充は 1 回に
  まとめ、1 ゴール最大 2 検索（0.6.0）。
- キャッシュのキーを `revision` にしていたため、実績統計の書き戻しごとに索引と埋め込みが
  作り直され、有料 API を再度叩いていた。検索が読む内容だけで動く `content_revision` を
  キーにする（0.6.0）。
- 既定の `RuleBasedSetSelector` だけが `min_relevance` を無視していた。既定構成でゲートが
  効いているかは、既定構成でテストする（0.6.0）。
- `Kernel(min_relevance)` の既定は 0.0。正解の関連度は 0.13 まで下がり、無関係な最良ヒットは
  0.52 まで上がるので単一の値では分離できない。値はデプロイ側が決める（0.6.0）。
- スコアの尺度を変えたらベンチマーク既定値も校正し直す（`--min-relevance` 0.55 → 0.35）。
- 関連度成分を差し替える改良は、第1層のランキング指標だけで採否を決められない。棄権ゲートを
  共有する第2層の Coverage / abstain 精度まで見る（cross-encoder 再ランクで Set F1
  0.582 → 0.431 に劣化。`benchmarks/README.md`）。
- 制約付き集合選択は LLM よりソルバーが強い。gpt-4o でも Set F1 0.628 対 greedy 0.720、
  過少選択が主因。制約は宣言メタデータとして解き、自然言語推論に委ねない（ADR 0005）。
- 権限フィルタを検索時に押し下げると escalate 能力が壊れる（abstain/escalate 精度 100% → 50%）。
  フィルタは「早いほど良い」わけではない（`benchmarks/README.md` Policy アブレーション）。
- 日本語ゴールの CJK バイグラム雑音（無関係でも 0.34）と、CJK 以外の非 ASCII の欠落は
  既知の未解決課題（PR #13）。

## カーネル実行ループ

- `max_tool_calls` が LLM ラウンド数を数え、判定がカウンタ加算の前にあった。上限 3 で最大
  12 回実行された。実行した呼び出しを実行前に判定し、カウンタはフレームに永続化して HITL 再開で
  二重計上しない（PR #1）。
- 実モデルは引数の型をよく間違える。スキーマ違反と存在しないツール名はモデルに差し戻す
  （`--max-input-repairs`、既定 2）。解決できない Secret は差し戻さない（0.5.0）。
- ツール出力は `--max-tool-output-tokens`（既定 8000）で切る。切るのは untrusted-content の
  区切りの内側で、閉じタグは必ず残す（0.5.0）。
- プロバイダのエラーは `failed` で終端させる。例外が外に出ると監査ログが書かれず、タスクが
  `running` のまま残った。終了コードは 2 → 1 に変わった（0.5.0）。
- 一時停止時の resume コマンドが `--granted-permission` と `--allow-side-effect` を落として
  いた。そのまま使うと承認済みのツールがスキップされても completed / exit 0（0.5.0）。
- `--strict` は「候補になった Tool / Agent が 1 つもモデルに届かなかった」と「どのリソースにも
  一致しなかった」を失敗にする。どちらも黙って成功していた経路（0.5.0）。
- `_finish_plan` が対応する assistant のツール呼び出しの無い `tool` メッセージを送り、
  OpenAI / Anthropic 双方が拒否して計画実行が毎回定型文に落ちていた（0.5.0）。
- 一時停止メッセージが勧める `human_approved=True` では safety 由来の停止や always-confirm は
  解除されない。実際に効く対処を示す（0.5.0）。

## セキュリティ・シークレット

- `.env` は最寄りを `override=False` で読み、OS 環境変数を優先する（`environment.py`）。
  カレントディレクトリ次第で挙動が変わる点は `改善策.md` に未対応として残っている。
- 伏せ字パターンは `marmo_core.secrets` の 1 か所に集約した。以前は 2 系統に分かれてずれていた。
  `github_pat_`、`AIza`、`xox[baprs]-`、`Basic`、`gsk_` / `xai-` と、401 が返すマスク済みの形を
  追加（4f18512e）。
- 監査レコードはキー名だけでなく値の形でも伏せ字にし、URL クエリ内のキーも対象にする
  （4f18512e）。
- 通知 webhook の URL は引数ではなく `MARMO_NOTIFICATION_<DEST>_URL` から読み、HTTPS 必須
  （2317432b）。
- `docs/threat-model.md` の運用: 未対処の Critical / High があるうちはリリースしない。
  最終レビューは 2026-07-23 で、0.5 / 0.6 の変更時には記録が追加されていない（要追記）。

## リソース定義・ローディング

- `description: >-` が文字列 `">-"` として読まれ、続く行が偽キーになっていた
  （1,000 件中 18 件）。ブロックスカラーのヘッダーを全部解釈する（10cc7d49）。
- ディレクトリ走査中の壊れた JSON は黙ってスキップされ「valid: 0 resources」で exit 0
  だった。警告して validate の要約に名前を出す。明示指定なら例外（10cc7d49）。
- パッケージ内の Markdown Skill はパッケージ名前空間で id を導出する（10cc7d49）。
- サンプルリソースは `python:` 参照で実装に解決し、必要な権限と副作用だけを宣言し、
  ファイルアクセスはカレントディレクトリ内に閉じる（2317432b）。

## ベンチマーク運用

- 約 260MB のサードパーティ Skill コーパスは `.gitignore` と `MANIFEST.in` の両方で除外し
  再配布しない。無ければ案内付きで停止する（0.5.0、ADR 0004）。
- 収集は許容的ライセンス（MIT / Apache-2.0 / BSD-3 / MIT-0）に限定し、出典を
  `resources/skills/SOURCES.md` に記録（6ef6ad03）。
- 生成できるコーパス `benchmarks/corpus/scale_corpus_*.json` はコミットしない（6ca748a0）。
- README の数値は隣にコミットした results JSON の同じ実行から取る。レイテンシは測定機の負荷で
  変わると明記する（3de214ca）。
- スコアリングを変えたら過去のスイープ結果（`semantic_weight` 0.9 が最良など）は無効になり、
  再スイープが要る。
- 結果 JSON には `_provenance.py` が commit SHA を刻む。SHA の違う結果を比較しない。

## 開発プロセス

- 大きな修正 PR には「判断が要るところ / Notes for reviewers」の節があり、既定値・終了コード・
  スコアの変化を明示している（PR #12、#13）。この形を PR テンプレートにした。
- `research/` ブランチは規則として定義されているが、まだ一度も使われていない。
- 改善提案（`改善策.md`）のうち実装済みは、SKILL.md ブロックスカラー、`--version`、Python の
  使い方の節、BM25F、キャッシュ、検索の無駄の削減。未実装は非同期化、公開 API の整理、
  `kernel.py` の分割、README の日本語併記、`python:` / `file:` 参照の安全性、カバレッジゲート
  など。実装状況は CHANGELOG で確認し、提案文書を実装の説明として引用しない。
