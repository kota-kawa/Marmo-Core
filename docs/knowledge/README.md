# Knowledge Base

再利用可能な知見の索引。作業ログ、一時的な状態、特定の PR にしか意味のない記述は
ここに置かない。そうした情報は PR 本文と `CHANGELOG.md` に残す。

| ファイル | 内容 | いつ読むか |
|---|---|---|
| `development_conventions.md` | プロジェクト構成、ビルド・テストコマンド、実装規約、命名、責務分割、テスト方針、サブエージェントの指定、AI 出力の品質確認 | コードを変更する作業で、該当する節を着手前に |
| `debugging.md` | 実モデル・検索・CLI・パッケージングの不具合の切り分け手順 | 動作がおかしいときの最初の手がかりとして |
| `contracts-and-compatibility.md` | 公開 API、リソース定義、状態ファイル、監査ログ、CLI 終了コード、プロバイダ wire 形式の互換性契約と変更手順 | これらの表面に触る前に |
| `parallel_work.md` | サブエージェントと git worktree で作業を分ける判断基準と、分けた後の運用手順 | 並行作業をするときに |
| `experiment_runbook.md` | 実験の段取り（準備・段階実行・評価設計の約束・長時間ジョブ）と、Claude Code クラウドセッションとローカル PC（API、AWS Bedrock、GPU）での違い | 実験を始める・再開する前に |
| `lessons_from_history.md` | git 履歴と PR から抽出した過去の失敗と教訓 | 該当領域を触る前に、同じ轍を踏まないために |

知見を追加したら、この表と `AGENTS.md` の「ドキュメントの参照先」を同じコミットで更新する。
設計判断そのものは `docs/decisions/` に ADR として書き、ここには書かない。
