# Module 学习日志记录器

## 这个 Skill 的职责

在进入新 Module 之前，将上一个 Module 的讨论内容整理为一个课程文件，写入 `lessons/` 文件夹，格式与现有课程文件保持一致。

---

## 第零步：读取参考格式

先用 Read 工具读取 `lessons/module1-what-is-agent.md`，理解课程文件的格式规范：
- 一级标题：`# Module X：主题名称`
- 二级章节：`## X.1 小节标题`（带编号）
- 内容风格：概念解释 + 代码块/示意图 + 表格
- 底部导航：`*上一课：... 下一课：...*`

> 为什么要先读参考文件？确保新生成的文件和已有文件风格完全一致，整个 lessons/ 文件夹看起来像同一个人写的。

---

## 第一步：确认记录范围

从对话历史中识别：
- **Module 编号和主题**：例如 Module 4「工具调用原理」
- **对应的文件名**：按 `moduleX-[主题英文缩写].md` 命名，例如 `module4-tool-use.md`
- **讨论的核心内容**：本次 Module 实际聊了什么

检查 `lessons/` 下是否已存在同名文件：
- 不存在 → 创建新文件
- 已存在 → 告知用户并询问是否覆盖

---

## 第二步：提炼内容，按课程格式组织

从对话历史中提炼，组织为以下结构：

### X.1 核心概念
把本 Module 最重要的 1-3 个概念写清楚，每个概念：
- 先给一句话定义
- 再用代码块或示意图说明（优先用示意图/代码，少用纯文字）

### X.2 原理 / 工作方式
解释"为什么是这样"，用具体例子驱动，不写抽象理论。

### X.3 和前面知识的连接
明确说明本 Module 的内容如何建立在之前 Module 的基础上。

### X.4 用户的理解与问答
把对话中用户说出的理解、提出的好问题、被纠正的误解记录下来。
用引用格式标注用户原话：`> "用户说的话"`

### X.5 动手成果（如果有）
列出本 Module 创建或修改的文件，每条一句话说明用途。

### 关键术语表（如果概念较多）
用表格整理本 Module 出现的新术语。

---

## 第三步：写入文件

用 Write 工具将内容写入 `lessons/moduleX-[topic].md`。

文件末尾必须加导航链接：
```
---

*上一课：[Module X-1 - 主题](./moduleX-1-xxx.md)*
*下一课：[Module X+1 - 主题](./moduleX+1-xxx.md)*（如果已知）
```

---

## 第四步：更新 README 进度

用 Read 工具读取 `README.md`，将已完成的 Module 从 `[ ]` 改为 `[x]`，用 Edit 工具执行修改。

---

## 第五步：告知用户

```
✓ lessons/moduleX-[topic].md 已创建
✓ README 进度已更新

现在可以开始 Module X+1 了。
```

---

## 异常处理

- **讨论内容不足，某个章节没有素材**：该章节写"本次讨论未涉及，待后续补充"，不要编造内容
- **文件已存在**：询问用户后再决定是否覆盖，绝不静默覆盖
- **不确定文件命名**：先问用户确认主题英文缩写再创建
