# 写作风格规范

## 核心原则

1. **读者优先**：假设读者是刚接触这个项目的开发者
2. **精准不啰嗦**：每句话都有信息量，删掉废话
3. **代码说话**：复杂逻辑用示例代码，不要纯文字解释

## 语言规则

### 描述函数时
- 用动词开头：「解析...」「返回...」「检查...」「转换...」
- 不写废话：❌「这个函数用于...」 ✅「解析 JWT token 并返回用户信息」
- 必须说明副作用（如果有）：「注意：此方法会修改传入的 options 对象」

### 描述参数时
- 说清楚边界条件：「必须是正整数」「可为空，默认值为 xxx」
- 说清楚格式：「ISO 8601 格式的日期字符串，如 2024-01-01」

### 不确定时的处理
- 如果代码逻辑不明确，在文档中标注：`⚠️ 待确认：此参数的作用待原作者确认`
- 不要猜测后当作事实写进文档

## 格式规则

- 标题层级最多 3 级（#、##、###）
- 代码块必须标注语言
- 表格用于参数列表，不用于普通说明
